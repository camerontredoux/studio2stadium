# Roster Pages Command Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refresh `/admin/dancers` and `/admin/coaches` to match the `/admin` landing page's command-center visual language: replace the generic toolbar with a stat-strip header that doubles as the status filter, and add real operator affordances (columns popover, density toggle, always-visible Export, filter chips).

**Architecture:** One new AdonisJS backend endpoint (`GET /orgs/:slug/events/:id/rosters/stats?type=…`) that returns `{ total, active, pending }` in a single Drizzle query using Postgres `count(*) filter (…)`. One new React component (`<RosterPageHeader>`) that mirrors the existing `EventHeader` + `StatCell` structure. A consolidated `DataGrid` refactor that adds columns/density/export/chips with `localStorage` persistence and removes the now-redundant `title`/`subtitle` props. Both roster pages rewire to the new header + new DataGrid props.

**Tech Stack:** AdonisJS v6 + Drizzle + VineJS (backend); React 19 + TanStack Router + TanStack Query + openapi-react-query + BaseUI (frontend). Japa for backend tests. **No frontend unit tests** — the frontend has no existing vitest test harness or `@testing-library/react` installed, and bootstrapping one is out of scope. Frontend verification is typecheck (`pnpm build`) + lint (`pnpm lint`) + user's browser check.

**Reference spec:** `docs/superpowers/specs/2026-04-11-roster-pages-command-center-design.md`

**Parallelization plan:**
- **Wave 1 (parallel):** Tasks 1, 5, 6, 7 (four independent subagents — backend scaffold, component, DataGrid refactor, label rename).
- **Wave 2:** Task 2 (after 1 — same backend module).
- **Wave 3:** Task 3 (after 2 — regenerates types that Task 4 depends on).
- **Wave 4:** Task 4 (after 3 — consumes regenerated types).
- **Wave 5 (parallel):** Tasks 8 and 9 (after 4, 5, 6, 7 — wire dancers and coaches, different files).
- **Wave 6:** Task 10 (foreground, after 8 and 9 — final verification).

```ts
import { DatabaseService } from "#database/service";
import { inject } from "@adonisjs/core";
import { eventRosters } from "#database/schema/org-events";
import { and, eq, sql } from "drizzle-orm";
import type { Validator } from "./validator.ts";

@inject()
export class StatsRosterService {
  constructor(private db: DatabaseService = new DatabaseService()) {}

  async execute(eventId: string, q: Validator) {
    const [row] = await this.db.use((db) =>
      db
        .select({
          total: sql<number>`count(*)::int`,
          active: sql<number>`count(*) filter (where ${eventRosters.userId} is not null)::int`,
          pending: sql<number>`count(*) filter (where ${eventRosters.userId} is null)::int`,
        })
        .from(eventRosters)
        .where(
          and(
            eq(eventRosters.eventId, eventId),
            eq(eventRosters.type, q.type),
          ),
        ),
    );
    return {
      total: row?.total ?? 0,
      active: row?.active ?? 0,
      pending: row?.pending ?? 0,
    };
  }
}
```
