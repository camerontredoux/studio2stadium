# Studio 2 Stadium

pnpm monorepo for the collegiate dance recruiting platform. Domain terms (Org, Org Event, Platform Event, Dancer, Coach, Roster Entry) are defined in `CONTEXT.md`; use them in code and prose. That file's opening lines describe the separate marketing-site repo, but its glossary applies here.

## Layout

- `apps/backend`: AdonisJS 6 API with Drizzle on Postgres. Owns all business logic, auth, payments, uploads, cron jobs, and realtime. Deployed to Fly.io.
- `apps/frontend`: React 19 SPA (Vite, TanStack Router and Query). Talks only to the backend. No hosting config lives in this repo.
- `apps/events`: Go worker that drains an AWS SQS queue and writes notification rows to Postgres through GORM. It has no HTTP surface. Not a pnpm workspace member.
- `packages/emails` (`@stos/emails`): React Email templates, built with tsup to `build/`. Only the backend imports it, so rebuild it after editing a template.
- `packages/openapi` (`@stos/openapi`): vendored fork of `@tuyau/openapi` that provides the `.openapi()` route macro and generates the spec.
- `docs/adr/`: accepted decisions for Org Events and Event Tiers. Read before changing tier or purchase behavior.
- `docs/superpowers/`: dated plans and specs. Historical; the code wins when they disagree.
- `apps/backend/CLAUDE.md` and `apps/frontend/CLAUDE.md` load when you work in those apps. Parts are stale; the corrections below take precedence.

## Vertical slices

Both apps group code by feature, not by layer.

### Backend: `apps/backend/app/modules/{domain}/{feature}/`

- Canonical example: `app/modules/event-tiers/` with `routes.ts` and the `checkout/` slice.
- A slice holds `controller.ts` (`@inject()`, validates, calls the service), `service.ts` (logic, `execute()`), `validator.ts` (VineJS), and optional `event.ts`.
- Feature folders are kebab-case verb-noun: `get-school`, `delete-org`.
- `routes.ts` sits at the domain level and imports controllers with explicit `.ts` extensions. Each route carries `.openapi({...})` metadata.
- Register a new domain by importing its `routes.ts` in `start/routes.ts`. Register a new `event.ts` in `start/events.ts`.
- Scaffold with `node ace make:feature <feature> <domain>` (stubs in `commands/stubs/make-feature/`).
- Tests sit in the slice as `service.spec.ts`, `validator.spec.ts`, and `routes.spec.ts`. The `functional` suite in `adonisrc.ts` lists every glob it picks up.
- Query through `DatabaseService` (`app/database/service.ts`): `use()` and `tx()` map Postgres errors to `E_*` exceptions from `app/exceptions/`.
- Cross-domain code lives in `app/shared/`, `app/utils/`, `app/auth/`, and `app/payments/`. Cron job classes live in top-level `services/` and are scheduled in `start/cron.ts`. One-off backfills are ace commands in `commands/`.

### Frontend: `apps/frontend/src/features/{feature}/`

- Canonical example: `src/features/favorites/` with `page.tsx`, `api/queries.ts`, `api/mutations.ts`, and `components/`, mounted by `src/routes/_app/(routes)/resources/favorites.tsx`.
- Route files stay thin: guards in `beforeLoad`, then `component:` from the feature.
- A feature never imports another feature (`eslint-plugin-boundaries`) and never imports its own parent barrel (`..`); import the specific file instead. Put shared code in `components/`, `lib/`, `shared/`, or `utils/`.
- Zod schemas sit in `api/schemas.ts` in most features.
- `src/routeTree.gen.ts` is generated by the router plugin.
- Specs are colocated `*.spec.ts(x)`.

## How the pieces talk

- Frontend to backend: `openapi-fetch` client in `src/lib/api/client.ts`, base URL `VITE_API_URL`, cookie sessions (`credentials: "include"`). In dev, Vite proxies `/api` and `/__transmit` to `localhost:3333`.
- API types: `src/lib/api/types.d.ts` is committed and generated by `pnpm frontend types` from the running backend's `/openapi`. After changing a backend route or response shape, run `pnpm backend make:docs` (updates committed `apps/backend/openapi.json`), then regenerate the frontend types with the backend running.
- Realtime: the backend serves SSE through AdonisJS Transmit, fanned out over Redis pub/sub (`app/shared/realtime/`). The frontend subscribes through `use-transmit.ts` and `use-realtime.ts`.
- Backend to events worker: the backend writes rows to the `outbox` table (`app/database/outbox-service.ts`). The `publish-outbox` cron in `start/cron.ts` sends them to SQS every 10 seconds. `apps/events` consumes the queue.

## Infrastructure

Env var names are declared and validated in `apps/backend/start/env.ts`; `.env.example` lists the local set.

- Postgres on Supabase: `DATABASE_URL` points at Supabase's transaction pooler (pgbouncer), which rejects prepared statements and may move statements across connections. Read the comments in `bin/migrate.ts` and `app/database/schema/cron.ts` before touching connections, migrations, or advisory locks.
- Migrations: edit `app/database/schema/`, run `pnpm backend db:generate`, and commit the output in `app/database/drizzle/`. On deploy, Fly runs `node bin/migrate.js` (compiled from `bin/migrate.ts`) as its `release_command`; a failed migration aborts the release.
- Cloudflare R2: the `r2` disk in `config/drive.ts` uses the AdonisJS Drive S3 driver with `R2_KEY`, `R2_SECRET`, `R2_BUCKET`, `R2_ENDPOINT`, and `DRIVE_DISK`. Files are public.
- Cloudflare Stream hosts videos: TUS uploads and deletes in `app/modules/videos/` and `app/modules/admin/`, webhooks verified by `app/middleware/routes/verify-cloudflare-webhook.ts`. Env: `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_STREAM_TOKEN`, `CLOUDFLARE_STREAM_URL`, `CLOUDFLARE_WEBHOOK_SECRET`.
- `CLOUDFLARE_DEPLOY_HOOK` rebuilds the marketing site when admins change blog posts or applications.
- Redis (`config/redis.ts`, `session` and `cache` connections): sessions and auth version keys, rate limiting (`LIMITER_STORE`), the cache, and Transmit pub/sub. Not a job queue.
- AWS: SES sends mail (`config/mail.ts`); SQS carries outbox events (`SQS_*`).
- Stripe: `config/stripe.ts` and `start/payments.ts`; Event Tier and subscription price IDs come from `STRIPE_PRICE_ID_*`.
- Sentry: `instrument.ts` loads first in `bin/server.ts` and is a no-op without `SENTRY_DSN`.
- Fly.io backend: root `fly.toml` (app `studio2stadium-dev`, `iad`, health check `/health`) built from the root `Dockerfile`. `.github/workflows/deploy.yml` deploys on push to `main` touching backend paths. It is the only workflow, so no CI runs tests or lint.
- Fly.io events worker: `apps/events/fly.toml` (`studio2stadium-events-dev`). No workflow deploys it.
- The root `Dockerfile` pins Node 24.19 because 24.20 breaks the OpenAPI command index build; read its header before changing the base image.

## Commands

Root scripts forward to apps: `pnpm backend <script>`, `pnpm frontend <script>`, `pnpm emails <script>`. Each app's `package.json` is the source of truth.

- Local services: `docker compose up db redis` (Postgres 18 and Redis). The compose `event-server` service needs `apps/events/cmd/.env`.
- Backend tests need a migrated `s2s_test` database (`apps/backend/.env.test`). Test bootstrap does not create or migrate it, and tests delete rows from the tables they use.
- One backend test file: `cd apps/backend && node ace test --files "app/modules/event-tiers/checkout/service.spec.ts"`.
- Frontend `pnpm test` starts Vitest in watch mode; use `pnpm frontend exec vitest run` for a single pass.
- Before finishing: `pnpm backend typecheck`, `pnpm backend lint`, `pnpm frontend lint`, and `pnpm frontend build` (which type-checks).

## Pitfalls

- `apps/backend/CLAUDE.md` names test files `test.ts`; real tests are `*.spec.ts`. Several `package.json` import aliases (`#controllers`, `#models`, `#events`, `#listeners`, `#services`) point at directories that do not exist; the real `services/` is top-level and imported by relative path.
- `apps/frontend/CLAUDE.md` cites `src/lib/access.ts` and `src/hooks/`; the code has `src/lib/access/`, `components/hooks/`, and `lib/session/`.
- Org Events and Platform Events use different tables and modules (`orgs`/`organizations` versus `events`). Keep them apart, as `CONTEXT.md` requires.
- Cron schedules fire on every Fly machine, and two or more run. A job that must run once per tick wraps its work in `withCronClaim` from `app/shared/cron/claim-run.ts`.
- `apps/backend/scratch/` and `apps/frontend/examples/` are throwaway material; never import from them.
